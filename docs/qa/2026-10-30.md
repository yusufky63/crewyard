## How it was run

- Screenshot mode (`CREWYARD_SHOT`) on this Windows 11 machine, whose display runs at 150%. `CREWYARD_SHOT_SCALE=1` and `=2` force 100% and 200% (new in this change), `density=compact` sets the density, `fixture` serves the screenshot data. One Electron run at a time; each process tree was killed afterwards.
- The full product (all axes × all screens × all states) is about 4,000 shots. This run covers each axis value at least twice across the screens, every screen at the hardest corner (960 px, 200%, compact), and the new UI (usage ledger, timeline, keyboard map) in dark and light at 1280 and 1920 px in `en` and `tr` in both densities, paired so every value of each axis appears.
- 200% at 960 × 640 DIP is the same layout a 1920 × 1080 display gets at 200%: the minimum window width.

## Keyboard pass

- `?` and `F1` open the map (seen in screenshot runs with `keys=open`); it is a native modal `<dialog>`, so `Esc` closes it and focus returns to the opener as in the other dialogs (not exercised by hand); `?` typed in a field stays text (code path, not exercised).
- `G` then `T / I / G / L / P / H` jumps to a screen when a project is open (new; DESIGN.md §7 listed it, nothing implemented it).
- `Ctrl K`, `Ctrl B`, `Ctrl Enter`, `F`, `Esc`, `Alt` + arrows, `Shift F10`, `+ / -` and the diff-review keys now match through `keys.ts`; `keys.test.ts` fails if a registered shortcut has no handler or a handler matches an unregistered one.
- Checked with unit tests and in screenshot runs, not by hand on a live session.
